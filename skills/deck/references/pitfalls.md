# Pitfalls

Applies to: a final self-check before hand-over. These are the common failure modes of a deck built without this skill, most frequent first, each with the place its rule lives.

## Common Failure Modes

| # | Failure | Rule |
|---|---|---|
| 1 | Titles written as phrases or sentences ("Three Steps Behind Every Photo") when a plain noun was available ("Current Pipeline") | `style.md` §Titles and Subtitles |
| 2 | Text boxes carrying 40-word paragraphs labelled "Interpretation" instead of a table or numbered points | `style.md` §Body Text |
| 3 | Numerals on slides that resolve to no registry row, especially derived percentages, roundings and computed monthly costs | `build.md` §Figures Registry |
| 4 | Vendors and models euphemised ("the paid outside service") although naming was cleared | `style.md` §Names, Codes, Sources and Vendors |
| 5 | Pilot or model-judged numbers rendered as hero stat tiles | `style.md` §Numbers on the Slide |
| 6 | A caveat footnote on most slides | `style.md` §Footnotes |
| 7 | No speaker notes | `style.md` §Speaker Notes |
| 8 | The file never opened; layout "verified programmatically", with a real overflow shipped | `workflow.md` §5 Check, `build.md` §Checks |

## Further Rationalisations

These complement `review.md` §Rationalisations to Refuse.

| Thought | Reality |
|---|---|
| "The derived number is fine, its inputs are in the registry" | Give it its own row with the formula in `claim`. |
| "Calling it 'the outside service' is safer" | If naming is cleared, name it; ask once if unsure. |
| "A caveat on every slide is more honest" | Basis footnote yes; caveats belong in notes unless the number misleads without them. |
| "The checkers passed, so the layout is fine" | The checkers estimate. Read the previews and open the file. |
