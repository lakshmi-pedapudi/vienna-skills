# Deck Building and Review

## Overview

A workflow for slide decks generated by python-pptx from one deterministic script, distilled from repeated build-and-review cycles on board, leadership, workshop and partner decks.

**Core principle:** the script is the source of truth and the `.pptx` is disposable. Charts and tables carry the content, text is short numbered points with bold lead-ins, every number resolves to one registry row, and nothing internal appears on a slide that leaves the organisation.

**Scope:** this skill carries rules, not any one deck's content. No number, model name, vendor, denominator or slide title in this skill or its templates belongs to the deck in front of you: every figure comes from that deck's own registry, and every claim from its own source data. Where an example names a subject, the rule transfers and the subject does not.

## When to Use

- A new deck for any audience: board, leadership, funder, partner, customer, workshop, internal team.
- Review comments arrived: a `_review.pptx` with prefixed comment boxes, Google Slides comments, or a numbered list.
- A deck has degraded through patching and must be rebuilt from raw data.
- A hosted page or long document must be cut into slides, or a deck exported to Google Slides or PDF.

**When not to use:** the HTML page itself (use the artifact skill, if installed), a research paper (use the paper skill, if installed), an email to stakeholders, a document whose deliverable is a Word or PDF file rather than slides.

## Workflow

**Session start**

1. Read the project's rules file (`CLAUDE.md` or `DECK_PLAN.md` in the deck folder) and its status memory. If neither exists, create both from `templates/`. Rules carry numbers; add new rules with the next number, never re-derive style from scratch.
2. Confirm audience, occasion, slide budget, and whether the deck leaves the organisation.
3. Read `references/style.md`. The title rule, the word bans and the no-names rule apply to every slide, including the appendix and the speaker notes.

**Phases**

| Phase | Output | Detail |
|---|---|---|
| 0 Recall | Rules file, status memory, prior decks in the family | `references/workflow.md` §0 |
| 1 Collect | `materials/` drop zone, `topics/<slug>.md` per topic, saturation declared per topic | `references/workflow.md` §1 |
| 2 Skeleton | Section list with ordering reasons, slide budget, sub-task allocation; confirmed at a checkpoint before any build | `references/workflow.md` §2 |
| 3 Draft | `DECK_DRAFT.md` slide by slide, self-consistency pass | `references/workflow.md` §3 |
| 4 Build | `build_deck.py` on `scripts/deck_primitives.py`, `figures.csv` registry, charts as SVG and PNG | `references/build.md` |
| 5 Check | Gate scripts, preview PNGs read, file opened, PDF checked | `references/build.md` §Checks |
| 6 Review | Comments extracted and generalised into numbered rules; rules, script and deck updated together; convergent loop; `REVIEW_LOG.md` | `references/review.md` |
| 7 Ship | Version archive, external scrub, Google Slides or PDF, pre-read sibling | `references/workflow.md` §7 |
| 8 Close | `SESSION.md`, status memory, hand-off note | `references/workflow.md` §8 |

Phases repeat. A review round re-enters at 2 or 3, never at 4 alone.

**Checkpoints:** stop and ask at topic segregation, skeleton and budget, narrative spine, and before any restructure, even in bypass mode (`references/workflow.md` §Checkpoint Questions). Nowhere else.

**Session close:** write or update `SESSION.md` in the deck folder (sources consulted, produced, reproduce commands, claim set with sources, caveats, still open) and the status memory (current version, archived versions, rules added this round, open review items, next step). The status memory must let a cold session rebuild the deck with no memory of the conversation.

## Quality Standards

### Non-Negotiables

**Wording**
- Titles are plain nouns, 1 to 4 words; the takeaway goes in the body (`style.md` §Titles and Subtitles).
- Chart or table first; text only as short numbered points with bold lead-ins, never a paragraph (`style.md` §Body Text).
- Plain English: no em-dashes, AI tells, consultant jargon or invented vocabulary (`style.md` §Words).
- No AI-tell sentence shapes: "not A, but B" pivots, padded lists, stacked adjectives, preambles, taglines (`style.md` §Sentence Shapes).
- No names, role attributions, internal codes, task ids or references to other documents on an external deck, notes included (`style.md` §Names, Codes, Sources and Vendors; §External Decks).

**Numbers**
- Every number comes from `figures.csv` by key; derived values get their own row; unknown keys fail the build; pending numbers render visibly with an owner (`build.md` §Figures Registry).
- One hero number per slide, only for measured, settled good news; every rate names its base (`style.md` §Numbers on the Slide).
- Basis footnotes yes; caveat footnotes rare; every content slide has speaker notes (`style.md` §Footnotes, §Speaker Notes).
- One deck per working set; never carry a figure from one deck's registry into another (`workflow.md` §0).

**Visuals**
- Native text boxes and tables; images only for flowcharts, architecture and charts with axes (`build.md` §Primitives).
- Charts via matplotlib and diagrams via Graphviz, saved as SVG and PNG; never Mermaid; no number baked into an image (`build.md` §Charts and Diagrams).
- Diagrams carry structure, no measurements, no title of their own (`figures.md` §Drawing Rules).

**Process**
- Skeleton approved before build; proposed rewrites shown before the live file changes; change exactly what was asked (`workflow.md` §2, `review.md` §Working Agreements).
- Review is a convergent loop: two to three passes, stop when two agree (`review.md` §Convergent Review Loop).
- Snapshot before any restructure; anything already sent outside is frozen (`workflow.md` §7).

### Gate Scripts

All live in `<skill-dir>/scripts/`. Run them after every build and before every hand-over.

| Command | Pass criterion | Key options | Does not catch |
|---|---|---|---|
| `check_words.py <deck>.pptx` | Exit 0, "0 hit(s)" | `--words FILE` (default `house_words.json`), `--codes REGEX`, `--names FILE`, `--allow REGEX`, `--external`, `--no-notes` | Sentence shapes, tone, misleading framing |
| `check_figures.py --deck <deck>.pptx --registry analysis/figures.csv` | Exit 0, "PASS" | `--charts DIR`, `--exempt REGEX`, `--exempt-file FILE`, `--strict` | A real number used against the wrong claim |
| `check_layout.py <deck>.pptx` | Every warning looked at on the slide | `--foot-rule INCHES` | Exact wrapping; it estimates |
| `preview_slides.py <deck>.pptx` | Every PNG read; nothing blank, clipped or off the page | `--out DIR` | Pixel-accurate rendering, fonts |
| `extract_review_comments.py <deck>_review.pptx` | Comment count reported | `--prefix TEXT` (repeatable, default `REVIEW:`) | Comments without the prefix, Google Slides comments |

Then open the `.pptx` and the exported PDF.

### Red Flags

Stop and re-read the relevant reference when any of these appear in your own output or plan:

- A title that could be read aloud as a sentence.
- A number in the script that is not `fig("key")`, or a chart drawn from a number that exists only on a slide.
- A person's name, an internal code, a ticket id, or "as discussed" on any slide or note of an external deck.
- A hero tile carrying a rejection rate, a failure share or a pilot result.
- Editing the `.pptx` by hand, or building a new deck when told to augment the existing one.
- A rebuild handed over without running the gate scripts and opening the file.
- Reporting a list of defects as fixed without re-checking each one (`review.md` §Working Agreements, item 8).
- A table, chart and takeaway on the same slide that disagree.
- A euphemism where the vendor or model name is cleared for use.
- A caveat footnote on most slides, or a content slide with no speaker notes.

## Limitations

- python-pptx only: no slide masters or template inheritance, and Google Slides is reached only by importing the `.pptx`.
- No true renderer: `preview_slides.py` and `check_layout.py` estimate text wrapping from average glyph width, so the real file must still be opened.
- `check_figures.py` checks that a number exists in the registry, not that it is used against the right claim.
- Sentence shapes, tone and framing are not machine-checked; they are a self-review item.
- Checkpoint questions use the AskUserQuestion tool, which is specific to Claude Code.
- Install commands assume macOS (`brew`); use the system package manager elsewhere.
- Build scripts must locate the skill through `DECK_SKILL_DIR` or an explicit path.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Slides blank after a restructure | The build error was swallowed: check the script exits 0, then open the file |
| Table sits on the footnote | A wrapping cell grew the row: shorten text, widen the column, or raise the table |
| `ModuleNotFoundError: deck_primitives` | Set `DECK_SKILL_DIR`, or expand `~` before adding the path to `sys.path` |
| Images missing in the deck | Use absolute paths (`CH / "name.png"`), never bare strings |
| Deck is 4 MB or more | `downscale()` chart PNGs to about 1300 px before embedding |

The full list is in `references/build.md` §Pitfalls.
